# ADR 0008 — Attach hardening headers in the application, not only at the edge

- **Status:** Accepted
- **Date:** 2026-11-08 (beta-readiness pass)

## Context

The deployment served no `X-Content-Type-Options`, `X-Frame-Options`, CSP,
`Referrer-Policy`, or `Permissions-Policy`. Two properties were unaddressed:

1. The app is served on two paths. The JSON API is answered by the Python function
   (`api/index.py`); the SPA document is served statically by Vercel for non-`/api`
   paths. A header set in only one place leaves the other unprotected.
2. A browser applies a header only on the response it actually receives. A 401 or a
   404 answered before the route runs is exactly the kind of response an attacker
   probes, so hardening that only decorates success responses is close to useless.

Clickjacking mattered here specifically: the guest's approve and refund controls sit
on an ordinary page, and a third-party frame could overlay a click target on them.
The guest cookie is `SameSite=Lax`, which does not stop same-site framing.

## Decision

- Add an outermost ASGI middleware (`SecurityHeadersMiddleware` in
  `backend/pact/main.py`) that appends the hardening headers to **every** response
  start, success or error. It never overwrites a header a route set itself.
- Register it last so it is the outermost layer, ahead of CORS and the body cap.
- Set the same headers for the statically-served SPA document in `vercel.json`,
  scoped to non-`/api` paths so the function responses are not double-decorated.
- Keep the CSP to framing/embedding directives only (`frame-ancestors 'none';
  object-src 'none'; base-uri 'self'`). No `default-src`/`script-src`/`style-src`:
  the Vite bundle uses inline styles, so a script/style policy would break the app,
  and shipping a policy that must be immediately relaxed is worse than a narrow one.

## Consequences

- Framing, MIME confusion on JSON/error bodies, and the job id leaking into the
  `Referer` on the PayPal approval redirect are closed on both serving paths.
- HSTS is already sent by the Vercel edge on every response, so it is not added
  here; the app does not set it either, so a plain-HTTP local run is not broken.
- The CSP is deliberately incomplete. A future, stricter policy (nonces or hashes
  for the bundle) is a separate decision and would need the build to cooperate.
- Regression coverage: `tests/test_security.py`
  (`test_every_response_carries_the_hardening_headers`,
  `test_the_csp_forbids_framing_but_does_not_constrain_the_bundle`,
  `test_a_header_already_set_downstream_is_not_overwritten`).

## Alternatives considered

- **Set the headers only in `vercel.json`.** Rejected: it does not cover the Docker
  image or any non-Vercel target, and it cannot see responses generated by the
  function. Doing both is what makes the guarantee hold on every target.
- **Set a full `default-src 'self'` CSP.** Rejected for now: it would block the
  bundle's inline styles and the app would not render; a CSP that must be loosened
  immediately is a false claim of protection.
- **Use a middleware library (e.g. `secure`).** Rejected: the header set is seven
  constants and one wrap of the ASGI `send`; a dependency is not earned by that.
