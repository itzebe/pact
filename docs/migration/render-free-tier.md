# Migrating PACT to Render (free tier)

Why: the Vercel team that hosts PACT is under a Hobby fair-use soft block
(`FAIR_USE_LIMITS_EXCEEDED` / `fluidCpuDuration`), so every project in it returns
`HTTP 402 DEPLOYMENT_DISABLED`. Render is a genuinely free alternative, and this
repository already ships the two files it needs: `Dockerfile` and `render.yaml`.

## What changed on this branch

Only `render.yaml`. It is the same one-service blueprint that already existed
(one container serves both the API and the built UI), adjusted to the **free**
compute plan:

- `plan: starter` → `plan: free`.
- Removed the `disk:` block. Free web services have an ephemeral filesystem and
  **cannot** attach a persistent disk, so all durable state must live in
  `DATABASE_URL` (already a required key).
- `DATABASE_URL` is now declared (`sync: false`) as a required secret.
- `PACT_DATA_DIR` → `/tmp/pact-data` (a writable path on the ephemeral filesystem).
- `LLM_BASE_URL` / `LLM_MODEL` → Groq `openai/gpt-oss-20b`, matching the deployed demo.

No application code, product scope, PayPal integration, or guest-first flow is
changed. `PACT_ALLOW_MOCK_PAYPAL=true` + `PACT_ENV=development` keep the labelled
"Simulated PayPal" demo path, exactly as the current deployment.

## Required environment variables (names only; never commit values)

Set in the Render service → Environment (the blueprint marks each one):

- `DATABASE_URL` — required; an external Postgres (Neon free tier recommended, since
  Render's own free Postgres expires 30 days after creation). Use the **pooled**
  endpoint; the settlement advisory lock uses a direct session and PACT derives the
  unpooled host automatically for Neon-style `-pooler` hosts.
- `PACT_AUTH_SECRET` — generated by the blueprint; the API fails closed without it.
- `PACT_ALLOWED_HOSTS` — set from the service host by the blueprint.
- `PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET` / `PAYPAL_ENVIRONMENT=sandbox` —
  sandbox credentials; optional only because the mock is enabled.
- `LLM_API_KEY` — an OpenAI-compatible key (Groq free tier). Without it the
  deterministic mock policy engine runs the whole lifecycle offline.
- `PACT_ENV=development`, `PACT_ALLOW_MOCK_PAYPAL=true` — the labelled mock demo.
- Optional, to match the current public demo exactly: `PACT_GUEST_SESSIONS=true`,
  `PAYPAL_SANDBOX_BUYER_EMAIL`, `PAYPAL_SANDBOX_BUYER_PASSWORD`.

## Deploy procedure

1. Create a **free Render account** (owner action) and choose **New → Blueprint**,
   pointing at this repository. Render reads `render.yaml`.
2. Provide the secret values above when prompted (`sync: false` keys).
3. Render builds the `Dockerfile` and starts the service; the health check is
   `GET /api/health`.
4. Verify: `https://<service>.onrender.com/` renders the SPA and
   `https://<service>.onrender.com/api/health` returns `{"status":"ok", …}`.

## Domain preservation

`pact-flame.vercel.app` cannot be moved (Vercel-managed subdomain). To keep a stable
public URL, add a custom domain the owner controls to Render and point its DNS at
Render. That is a DNS change and requires owner approval — not done here. Also note
`PACT_PUBLIC_URL` (currently `https://pact-flame.vercel.app`) is used as the PayPal
`return_url`; it must be updated to the new host when traffic is switched, or left
unset so the request host is used.

## Rollback

The Render deploy is additive; the Vercel project and its deployments are untouched.
To roll back, stop the Render service (or remove the custom domain) and, once the
Vercel team unblocks (~2026-12-09), `pact-flame.vercel.app` serves its existing
READY deployment again with no action.

## Free-tier limitations to expect

- Render free web services **spin down after 15 minutes** idle and take ~1 minute to
  spin back up; a judge's first request pays that cold start.
- Ephemeral filesystem: local files are lost on restart/redeploy — hence the required
  external `DATABASE_URL`.
- 750 free instance-hours/month per workspace; a spun-down service consumes none.
- Render's own free Postgres expires after 30 days, so prefer an external database.
